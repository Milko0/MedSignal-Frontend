# Phase 7 — Profile and settings (View 6: FR-13, FR-14)

**Goal:** the user can view and edit their profile, change their password, choose which alerts they receive and
the minimum reports threshold, log out, and delete their account.

**Backend endpoints:** `GET/PATCH/DELETE /profile`, `POST /profile/password`, `GET/PUT /profile/alert-settings`,
`POST /auth/logout`.

---

## 1. Backend facts

- `PATCH /profile` body `{ username?, email? }` (username 3–32, valid email) → `UserResponse`. Taken username/email
  → 409; invalid → 422.
- `POST /profile/password` body `{ current_password, new_password (>= 8) }` → 204. Wrong current password → 401
  (`InvalidCredentialsError`) — **this 401 must not log the user out** (see 2.4).
- `GET /profile/alert-settings` → `{ new_signal, label_updated, shortage_changed, new_recall, min_reports }`;
  `PUT` takes the full object and returns it.
- `DELETE /profile` → 204 and the current token is revoked server-side.

## 2. Tasks

### 2.1 `useProfileStore` (new)
- State: `alertSettings`, `savedSettings` (to detect unsaved changes), `loading`, `saving`, `error`, `fieldErrors`.
- Actions: `load()` (alert settings; the user object already lives in `useAuthStore`), `updateProfile(form)`
  (updates `authStore.user` with the response), `changePassword(form)`, `saveSettings()`, `deleteAccount()`
  (then `authStore` local logout without calling `/auth/logout`, since the token is already revoked), `reset()`.

### 2.2 `ProfileView.vue` (mock-up View 6)
- Left menu: Profile / Alert settings / Account — anchors to sections (single page, no sub-routes).
- **Profile card:** username + email inputs prefilled, "Save changes" enabled only when something changed;
  success toast; 409/422 under the field.
- **Password card:** "Change password" opens an inline form (current, new, confirm). Confirm-match and length rule in
  `authValidation.js`; wrong current → message under "Current password".
- **Alert settings card:** four `ToggleSwitch`es (New safety signal, Label updated, Shortage status changes,
  New recall) with the mock-up subtitles + "Minimum reports for signals" select (3/5/10/20/50/100). Save button
  (explicit save, not on every toggle — fewer writes and a clear "unsaved changes" state).
- **Account card:** "Log out" (Phase 2 action) and "Delete account" (danger) → confirm dialog requiring the user to
  type their username → `DELETE /profile` → redirect to `/auth` with a "Your account was deleted" notice.
- `ToggleSwitch`: make it accessible (`role="switch"`, `aria-checked`, keyboard Space/Enter) and add a test.

### 2.3 Use the threshold elsewhere
`min_reports` from alert settings becomes the default "Minimum reports" filter on `/signals` for logged-in users
(only when the URL has no `min`). Keep this in the signal store's `filtersFromQuery` defaults, passed in, not read
from the profile store inside the rule.

### 2.4 401 that is not a session expiry
Extend the Phase 2 rule: the `onUnauthorized` hook ignores 401s from `/auth/login`, `/auth/logout` **and**
`/profile/password`. Put the list in one constant (`core/constants/auth.js`) with a test.
