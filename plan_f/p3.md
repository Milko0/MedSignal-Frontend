# Phase 3 — Search and dashboard (View 2: FR-01, FR-06, FR-17, FR-18)

**Goal:** the landing page works for guests and users: typo-tolerant drug search (dashboard and navbar), summary
tiles, emerging signals of the latest quarter, and — for users — the latest alerts.

**Backend endpoints:** `GET /drugs?query=&limit=`, `GET /signals/emerging?quarter=&min_reports=&page=&page_size=`,
`GET /cabinet` and `GET /cabinet/alerts` (users only).

---

## 1. Backend facts

- `GET /drugs` needs `query` with at least 2 chars (else 422); returns `[{ rxcui, name, brand_names, matched, score }]`
  sorted by score. `matched` tells which name matched (e.g. a brand) — show it when it differs from `name`.
- Search results are **ingredients** (RxNorm `IN`), which is what Drug 360 and follows take.
- `GET /signals/emerging` returns the disclaimed envelope; `quarter` omitted = latest quarter; default
  `min_reports=3`. The response's `data.quarter` is the quarter actually used — show it in the card title.
- `trend` on each signal row is a list of PRR values per previous quarter → sparkline.

## 2. Tasks

### 2.1 Search (`DrugSearchBox.vue` + `useDrugStore`)
- `useDrugStore`: `searchQuery`, `results`, `searching`, `searchError`, action `search(q)` that ignores stale
  responses (keep a request counter; only the latest response is applied).
- `DrugSearchBox`: uses `useDebouncedSearch` (300 ms, >= 2 chars); dropdown list (name, brand names in muted text,
  "matched: X" when different); keyboard: up/down, Enter opens, Esc closes; "Search" button / Enter with no
  selection opens the top result. `compact` prop for the navbar version.
- Empty state: "No drug matches 'xyz'". Error state: "Search is unavailable, try again".
- "Try: amoxicillin ibuprofen metformin" chips fill the box and search.
- Selecting a result → `router.push({ name: 'drug', params: { rxcui } })`.

### 2.2 Dashboard store usage
- New store `useDashboardStore` (or actions on existing stores — pick one and keep it consistent): loads emerging
  signals (`page_size=5`) and, if logged in, cabinet + alerts in parallel (`Promise.allSettled`, so one failing
  card doesn't blank the page).
- Tiles (users): Medicines followed (`followed.length`), New alerts (`alerts.length`), Followed drug in shortage
  (count of `isInShortage(shortageStatus)`), Emerging signals this quarter (`emerging.total`).
  Guests see only the emerging-signals tile plus a "Create an account to follow medicines" call to action.

### 2.3 `DashboardView.vue` (mock-up View 2)
- Header: "Welcome back, {username}" for users, "Search drug safety and shortages" for guests.
- Search box, tiles row, two cards:
  - **Latest alerts** (users only): newest 4 alerts — dot coloured by `alertTone(type)`, drug name, message,
    relative time ("2 h ago" via a pure `relativeTime(iso, now)` rule with tests), "View all" → `/my-medicines`.
    Drug name: alerts carry only `drug_rxcui`; resolve it from `cabinet.followed` (followed drugs are the only
    ones that get alerts), fall back to the rxcui.
  - **Emerging signals this quarter**: table Drug / Reaction / Reports / PRR / Trend (sparkline), row click →
    `/signals?rxcui=…&reaction=…`; "Open signals" → `/signals?tab=emerging`.
- `DisclaimerFooter` with the `meta.disclaimer` from the emerging response.

### 2.4 Sparkline component
`components/charts/Sparkline.vue` — tiny inline SVG (not Plotly: 5 rows × Plotly is heavy), prop `values: number[]`.
Reused in Phase 5's signal table.

## 4. Live checks (`plan_f/p3_test/results.md`)

1. Type `ibuprofn` (typo) → `GET /api/drugs?query=ibuprofn&limit=10` → ibuprofen listed first.
2. Type a brand name (e.g. `advil`) → ingredient shown with "matched: ADVIL".
3. Type `a` → no request sent.
4. Guest dashboard: only `GET /signals/emerging` sent; no `/cabinet*` calls (no 401s in the console).
5. User dashboard: `/cabinet` and `/cabinet/alerts` sent with Bearer; tiles match the responses.
6. Emerging card title shows the quarter from the response; disclaimer text equals `meta.disclaimer`.
7. Stop the backend → cards show error + retry, page doesn't crash.
8. If no alerts exist yet (the worker has not dispatched any), note it under "Not exercised live" — covered by store tests.
