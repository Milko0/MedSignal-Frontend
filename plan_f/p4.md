# Phase 4 — Drug 360 (View 3: FR-02, FR-03, FR-10, FR-15)

**Goal:** `/drugs/:rxcui` shows the full picture of one ingredient: header with follow button, shortage status,
recalls, label, most reported reactions, monthly trend of the top reactions, and ranked alternatives while in
shortage. Dosage form / route can be narrowed.

**Fixes:** M9 (UI part), M11, M16, M17. **Backend endpoints:** `GET /drugs/{rxcui}/overview?dosage_form=&route=`,
`GET /drugs/{rxcui}/reaction-trend?months=`, `GET /shortages/{rxcui}/alternatives?dosage_form=&route=`,
`POST /cabinet/follows`, `DELETE /cabinet/follows/{rxcui}`.

---

## 1. Backend facts

- Overview is optional-auth: with a token, `is_followed` is filled in; without, it is `false`.
- Unknown rxcui → **404** `{ detail }`.
- `shortage.status` is `null` when the drug never had a shortage record. `shortage.dosage_forms` lists every form
  with a record → use it for the dosage-form selector.
- `recalls.linked_share` is the share of all recalls linked to a drug: counts are a **lower bound** → show a small
  note "at least" when `linked_share < 1`.
- `match_coverage` = share of reports resolved to an ingredient → show as a muted data-quality note.
- `top_reactions` is `[{ reaction, reports }]`; there is no `meta.disclaimer` on overview → use the constant.
- `reaction-trend` returns a flat list `[{ month: 'YYYY-MM', reaction, reports }]` for the top reactions.
- Alternatives: `items` already ranked (`rank`), `match_type` SAME_INGREDIENT | SAME_CLASS, `signal_profile`
  LOW | MODERATE | HIGH. Only meaningful when the drug is in shortage.
- Follow: 204; unknown ingredient → 404; requires login (401 as guest).

## 2. Tasks

### 2.1 `useDrugStore` (Drug 360 part)
- State: `current`, `trend`, `alternatives`, `selection { dosageForm, route }`, per-section `loading`/`error`, `notFound`.
- `loadDrug(rxcui, selection)`:
  1. overview (await — the page needs it),
  2. then in parallel (`allSettled`): trend (`months=12`) and, **only if** `isInShortage(current.shortage.status)`,
     alternatives with the same selection.
- `setSelection(...)` re-runs overview + alternatives (trend is not filtered by form).
- `toggleFollow()`: optimistic flip of `current.isFollowed`, call follow/unfollow, roll back + toast on failure;
  afterwards mark the cabinet store stale (`cabinet.invalidate()`) so My medicines refetches.
- Watch the route param: navigating from one drug to another (navbar search) must reload, not reuse the old drug.

### 2.2 Domain rules (pure, tested)
- `pivotTrend(points)` → `[{ reaction, months: [...], counts: [...] }]`, months sorted, missing months filled with 0,
  series ordered by total reports (desc), top 3 kept (mock-up: "Top 3 reactions").
- `formatShortage(shortage)` → `{ tone, title, subtitle }`: "Currently in shortage" / "Since 12 Sep 2026" /
  "3 of 12 packages affected", "No shortage reported" when `null`.
- `matchTypeLabel`, `signalProfileTone` (LOW green, MODERATE amber, HIGH coral).

## 4. Live checks (`plan_f/p4_test/results.md`)

1. Open a drug found via search → one `overview` call, one `reaction-trend?months=12` call; cards match the JSON.
2. A drug **in shortage** → `alternatives` call made, table filled; a drug **not** in shortage → no alternatives call.
3. Change dosage form → `overview?dosage_form=…` and `alternatives?dosage_form=…` re-sent.
4. Guest clicks Follow → sent to login, returns to the drug after login.
5. User follows → `POST /cabinet/follows` 204, button flips; reload → still "Following" (`is_followed: true`);
   unfollow → `DELETE` 204.
6. `/drugs/0000000` → 404 state.
7. Navbar search from one drug page to another → page reloads with the new drug.
8. Cleanup: unfollow, delete the test user.
