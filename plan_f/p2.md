# Phase 2 — Auth and session (View 1: FR-11, FR-12)

**Goal:** a user can register, log in, stay logged in across reloads, log out (token revoked server-side), and is
sent back to the login screen cleanly when the token expires. Guards and the navbar react to the session.

**Fixes:** M2, M3, M4, M5, M6. **Backend endpoints:** `POST /auth/register`, `POST /auth/login`,
`POST /auth/logout`, `GET /profile` (used as "who am I").

---

## 1. Backend facts that drive the design

- `POST /auth/register` body `{ username (3–32), email, password (>= 8) }` → **201** `UserResponse`, **no token**.
  Duplicate username/email → **409** `{ detail: "Username or email already registered" }`. Bad shape → **422**.
- `POST /auth/login` body `{ identifier, password }` (identifier = username or email) → `{ access_token, token_type }`.
  Wrong credentials → **401** `{ detail: "Invalid credentials" }`.
- JWT lifetime is `JWT_EXPIRE_MINUTES` (60 by default). No refresh endpoint (request B7).
- `POST /auth/logout` (Bearer) → **204**; the token's `jti` is revoked, later calls with it are **401**.
- Any bad/expired/revoked token on an **optional-auth** endpoint (e.g. Drug 360) is a **401**, not a silent
  guest — so a stale token must be dropped, or guest pages break too.
- No `GET /auth/me`; `GET /profile` returns the same `UserResponse`.

## 2. Session flow

```
login(form)    -> authApi.login({identifier, password}) -> session.set(token) -> profileApi.get() -> user
register(form) -> authApi.register(form) -> login({identifier: form.username, password: form.password})
restore()      -> token in storage? -> profileApi.get() -> user   (401 -> clear, stay guest)
logout()       -> authApi.logout() (ignore 401/network) -> session.clear() -> reset user stores
on 401 (any)   -> session.clear() -> user = null -> router to /auth?redirect=<path> (only if route needs auth)
```

## 3. Tasks

### 3.1 `authService` (application)
`createAuthService(authApi, profileApi, session)` with `login`, `register`, `restore`, `logout`, `hasToken`.
Pure orchestration — no Vue, no router.

### 3.2 `useAuthStore`
- State: `token` (ref, initialised from `session.get()`), `user`, `restoring`, `error`.
- Getters: `loggedIn = computed(() => !!token.value)` (reactive, fixes M5), `isAdmin`, `initials` (for the avatar).
- Actions: `login`, `register`, `restore`, `logout`, `handleUnauthorized()`.
- On logout / unauthorized also reset the user-scoped stores (`useCabinetStore().$reset()` style reset function
  in each setup store — add `reset()` actions to cabinet and profile stores).

### 3.3 Wiring the 401 handler without breaking layering
In `main.js` (composition-level code, allowed to know both sides):

```js
configureHttp({ getToken: tokenStorage.get, onUnauthorized: () => authStore.handleUnauthorized() })
await authStore.restore()          // before mounting, so guards see the real state
app.mount('#app')
```

`handleUnauthorized()` clears the session, sets `user = null`, and if the current route has `meta.requiresAuth`
pushes `{ name: 'auth', query: { redirect: route.fullPath } }`. Guard against loops: ignore 401s from
`/auth/login` itself (wrong password is a form error, not a session expiry) and from `/auth/logout`.

### 3.4 Guards (`router/guards.js`)
- `requiresAuth` and not logged in → `{ name: 'auth', query: { redirect: to.fullPath } }`.
- `guestOnly` and logged in → dashboard.
- After login/register, `AuthView` goes to `route.query.redirect` if it is an internal path (starts with `/`,
  not `//`), else dashboard.

### 3.5 `AuthView.vue` (mock-up View 1)
- Two cards: "Log in — Welcome back." and "Create account — Follow medicines and receive alerts.", labels above
  inputs as in the mock-up, "Continue as guest" link under them.
- Client validation mirrors the backend: username 3–32, valid email, password >= 8; identifier and password required.
  Show messages under the field; disable the button while submitting.
- Server errors: 401 → "Wrong username/email or password"; 409 → under username/email; 422 → `fieldErrors`
  mapped to fields; network → generic banner.
- Validation rules as pure functions in `src/domain/rules/authValidation.js` (with tests), not inline in the template.

### 3.6 Navbar
`AppNavbar.vue`: when logged out show "Log in"; when logged in show the avatar with initials (menu: Profile,
Log out) and the "My medicines" link. Badge and bell are wired in Phase 6.
