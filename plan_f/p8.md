# Phase 8 — Hardening, end-to-end runs and delivery

**Goal:** the integrated app works against **both** storage backends (`memory` and `databases`), builds and runs in
Docker behind Nginx, handles slow/failing calls gracefully, and the documentation describes what was actually built.

---

## 1. End-to-end runs on both backends

The course deliverable is the MongoDB + Redis backend; the in-memory backend is the reference. The UI must behave
the same on both (the backend's port conformance suite guarantees the API contract; this phase checks the screens).

| Run | Backend setup |
|---|---|
| A | `STORAGE_BACKEND=memory`, `data/clean` built from the real downloads |
| B | `STORAGE_BACKEND=databases`, `docker compose -f deploy/docker-compose.local.yml up -d`, data loaded, worker running (`python -m app.worker`) |

Script the full user journey once and run it on A and B (manual checklist in `plan_f/p8_test/journey.md`):
guest search → Drug 360 → signals filters → reports drawer → register → follow 3 drugs → My medicines →
alert settings → (B only) trigger a shortage change via the worker and see the alert + bell → dismiss → log out →
delete account. Record timings of the main calls (DevTools) to show the Redis-cached paths are fast
(`/cabinet`, shortage status) — useful evidence for the database part of the grade.

## 2. Resilience

- Global Axios timeout stays 30 s; Drug 360 and signals show a "still loading…" hint after 3 s.
- Network error / 5xx → section-level error with retry (already per phase); add a global offline banner
  (`navigator.onLine` + `online`/`offline` events) in `AppLayout`.
- 501 responses (admin stubs) are never called from the UI — grep check.
- Router `onError` for failed lazy-chunk loads → "A new version is available, reload" message.
- Toasts (`useUiStore`) rendered in `App.vue` — one place, `aria-live="polite"`.

## 3. Performance

- Plotly stays lazy-loaded (already a separate chunk); confirm with `npm run build` output that the initial bundle
  does not contain it.
- Lists are paginated server-side; no screen loads more than `page_size=100`.
- Search debounced (300 ms) and stale responses dropped (Phase 3).

## 4. Accessibility and look

- All inputs labelled; focus visible; tables have `<th scope>`; colour is never the only signal (chips have text).
- Palette only from `styles/tokens.css`; check against the six mock-ups side by side and list differences.
- Narrow screens (≥ 360 px): grids stack, tables scroll horizontally inside their card.

## 5. Build and deploy

- `npm run build` clean (no warnings that matter); `npm run preview` smoke test.
- Docker: `docker build -t medsignal-frontend .`; run with the backend compose (`--profile app`) → `http://localhost:8080`,
  confirm Nginx proxies `/api/` and deep links (`/drugs/123` reload) work (`try_files`).
- Virtual Lab: document the one line to change in `nginx.conf` (upstream address of the API VM).
- Check `.env.example`, `Dockerfile` and `nginx.conf` agree on `/api`.
