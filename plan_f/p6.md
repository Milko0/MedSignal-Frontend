# Phase 6 — My medicines (View 5: FR-15 to FR-18)

**Goal:** the user's medicine cabinet: followed drugs with their current status, filter chips, unfollow, the alert
list with dismiss one / dismiss all, the 30-day expiry note, and the alert bell + nav badge everywhere in the app.

**Fixes:** M7, M8 (UI). **Backend endpoints:** `GET /cabinet`, `POST /cabinet/follows`,
`DELETE /cabinet/follows/{rxcui}`, `GET /cabinet/alerts`, `DELETE /cabinet/alerts/{alert_id}`, `DELETE /cabinet/alerts`.

---

## 1. Backend facts

- `GET /cabinet` → plain array `[{ rxcui, name, shortage_status, packages_in_shortage }]` (Redis follows set +
  cached shortage status). No class / dosage form / latest event (request B5).
- `GET /cabinet/alerts` → plain array `[{ alert_id, type, drug_rxcui, message, created_at }]`, already without
  expired ones (30-day TTL, NFR-09). Alerts are produced by the worker (shortage poll, signal computation, label/recall
  updates) — a fresh user has none until an event happens for a drug they follow.
- Dismiss: 204 for one (`alert_id`) or all.

## 2. Tasks

### 2.1 `useCabinetStore`
- State: `followed`, `alerts`, `loaded`, `stale`, `loading`, `error`, `activeFilter` (`ALL|SHORTAGE|SIGNAL|LABEL|RECALL`).
- `load({ force })` — fetch both in parallel; skip when loaded and not stale (other pages call it freely).
- `invalidate()` — set by Drug 360 follow/unfollow (Phase 4).
- `unfollow(rxcui)` — optimistic remove with rollback + toast.
- `dismiss(id)` / `dismissAll()` — optimistic remove with rollback.
- `reset()` — on logout (Phase 2).
- Getters:
  - `rows` — followed drug + its newest alert (`latestAlertByRxcui`) → status chip: newest alert type if any
    (SHORTAGE amber, SIGNAL coral, LABEL teal, RECALL slate), else shortage status, else "No changes" (green).
    This is the B5 fallback; when the backend adds fields, only this getter changes.
  - `filteredRows` by `activeFilter` (SHORTAGE also matches drugs currently in shortage without an alert).
  - `unreadCount` = `alerts.length`, `followedCount`.
- Pure helpers in `domain/rules/cabinet.js` (with tests): `latestAlertByRxcui(alerts)`, `rowStatus(drug, alert)`.

### 2.2 Components (fill placeholders)

### 2.3 `MedicineCabinetView.vue`
- Title, "N medicines followed. Click a medicine to open its page.", "Find a drug to follow" → focuses the navbar search.
- Filter chips: All / Shortage / Signals / Label / Recalls.
- Two-column layout: rows left, `AlertList` right; stacks on narrow screens.
- Empty states: no follows ("You don't follow any medicine yet" + search box), no alerts ("No alerts in the last 30 days").
- `DisclaimerFooter` (signal alerts are shown here).

### 2.4 Freshness
- Refetch alerts when the window regains focus (`visibilitychange`) if the last fetch is older than 60 s — no polling loop.
